8) Search, Filter, Paginate Profiles (Public List)
-------------------------------------------------------------------------------
- URL: /api/v1/profiles/
- HTTP Method: GET
- Authentication: JWT (Bearer <access_token>)
- Headers:
  - Authorization: Bearer <access_token>
- Parameters (Query Parameters):
  - `page`: Page number (default: 1)
  - `page_size`: Profiles per page (default: 10, max: 100)
  - `college`: Filter by college name (case-insensitive)
  - `branch`: Filter by branch name (case-insensitive)
  - `year`: Filter by year (1 to 5)
  - `skills`: Filter by skills (comma-separated list, e.g. `python,django`)
  - `interests`: Filter by interests (comma-separated list, e.g. `ai,reading`)
  - `search`: General search string checking: username handle, full_name, bio, location, skills, interests
- Request Body: None
- Success Response (200 OK):
  {
    "success": true,
    "message": "Profiles retrieved successfully",
    "data": {
      "results": [
        {
          "id": 1,
          "username": "cyber_knight",
          "full_name": "Arthur Pendragon",
          "college": "Camelot University",
          "branch": "Computer Science",
          "year": 3,
          "skills": ["Python", "Cryptography"],
          "interests": ["Cybersecurity", "Blockchain"],
          "profile_photo": "https://solely-together-cricket.ngrok-free.app/media/profiles/avatar.png",
          "location": "England, UK"
        }
      ],
      "count": 1,
      "next": null,
      "previous": null
    }
  }
- Example Request:
  curl -X GET "https://solely-together-cricket.ngrok-free.app/api/v1/profiles/?college=Camelot+University&skills=python&search=Arthur" \
    -H "Authorization: Bearer <access_token>"

16. SUPABASE STORAGE INTEGRATION (PHASE 10)
--------------------------------------------------------------------------------

- Integrated with all user uploads:
  - Profile Images (UserProfile.profile_photo)
  - Community Icons & Banners (Community.icon, Community.banner)
  - News Images & Banners (News.image, News.banner)
  - Event Banners & Gallery (Event.banner, EventGalleryImage.image, EventSpeaker.photo, EventSponsor.logo)
  - Message Attachments (MessageAttachment.file)

- Validations & Size Limits:
  - Images (JPEG, PNG, WEBP, GIF): Maximum size 5MB. Automatic quality-75 compression.
  - Documents & Videos (PDF, Word, Excel, Zips, MP4, MOV, AVI, MKV): Maximum size 25MB.
  - Blocked Formats: Unsupported formats (like .exe) are rejected with a 400 Bad Request (ValidationError).
  - Simulates an automated virus check before upload.

- Storage Quotas:
  - Max storage size per user: 100MB cumulative uploads.
  - Exceeding the quota returns a 400 Bad Request (ValidationError).

- File Cleanup:
  - Deleting database model instances automatically cleans up associated physical files from Supabase storage and recovers user storage quota.

- Storage API Endpoints:

  POST /api/v1/storage/upload/
  - Description: Direct endpoint to upload files to Supabase Storage with all validations/compressions/quota checks applied.
  - Auth: Bearer Token (required)
  - Content-Type: multipart/form-data
  - Request Body:
    - file: The file binary.
  - Success Response (200 OK):
    {
      "success": true,
      "message": "File uploaded successfully.",
      "data": {
        "file_name": "filename.jpg",
        "url": "https://supabase.../filename.jpg",
        "size_bytes": 10240
      }
    }

  POST /api/v1/storage/signed-url/
  - Description: Request a temporary signed download URL for a file.
  - Auth: Bearer Token (required)
  - Request Body:
    {
      "file_name": "filename.jpg",
      "expires_in": 3600
    }
  - Success Response (200 OK):
    {
      "success": true,
      "message": "Signed URL generated successfully.",
      "data": {
        "signed_url": "https://..."
      }
    }

  GET /api/v1/storage/quota/
  - Description: Retrieve cumulative storage usage metrics for the authenticated user.
  - Auth: Bearer Token (required)
  - Success Response (200 OK):
    {
      "success": true,
      "message": "User storage quota retrieved.",
      "data": {
        "bytes_used": 1234567,
        "limit_bytes": 104857600
      }
    }

17. WEBSOCKET REAL-TIME SERVICE (PHASE 11)
--------------------------------------------------------------------------------

All WebSockets are powered by Django Channels. Redis is used as the channel layer.

- Authentication:
  WebSockets authenticate via the `token` query parameter:
  `ws://<host>/ws/channels/<channel_id>/?token=JWT_ACCESS_TOKEN_HERE`

- Endpoints & Consumers:

  1. Live Chat & Channel Presence:
     URL: `ws://<host>/ws/channels/<channel_id>/`
     Description: Connect to a specific community channel for live messaging, typing indicators, reactions, and online presence tracking.

     - Client Actions:
       - Send Heartbeat Ping:
         Request: `{ "type": "ping" }`
         Response: `{ "type": "pong" }`
       - Send Typing Status:
         Request: `{ "type": "typing", "is_typing": true }`
         Response: (Broadcasted to other users) `{ "type": "typing", "user_id": 12, "username": "thiru", "is_typing": true }`

     - Server Broadcasts (to group "channel_<channel_id>"):
       - User Presence Updates:
         `{ "type": "presence_update", "online_users": [{ "id": 1, "username": "thiru", "display_name": "Thiru" }] }`
       - Live Message Created:
         `{ "type": "message", "message": { ...message object... } }`
       - Live Message Edited:
         `{ "type": "message_edited", "message": { ...message object... } }`
       - Live Message Deleted:
         `{ "type": "message_deleted", "message_id": 456 }`
       - Live Reactions Added/Removed:
         `{ "type": "reaction", "message_id": 456, "reactions": [{ "emoji": "🔥", "count": 2 }] }`
       - Live Pinned/Unpinned Broadcast:
         `{ "type": "pinned_broadcast", "message_id": 456, "is_pinned": true }`

     - Throttling Rule:
       Clients are capped at a maximum of 5 messages/requests per second. Exceeding this triggers an error payload:
       `{ "type": "error", "message": "Rate limit exceeded. Maximum 5 messages per second." }`

  2. Live News Updates:
     URL: `ws://<host>/ws/news/`
     Description: Connect to the public news feed to listen for news publication events.
     - Server Broadcasts:
       - News Published:
         `{ "event": "news_published", "data": { ...news object... } }`

  3. Live Notifications Updates:
     URL: `ws://<host>/ws/notifications/?token=JWT_ACCESS_TOKEN_HERE`
     Description: Connect to user-specific channel to receive live notifications.
     - Server Broadcasts:
       - New Notification Alert:
         `{ "event": "new_notification", "data": { ...notification object... } }`

        - Request Body: { "user_id": 12, "role": "moderator" }
        - Success: Returns { "id", "username", "new_role" }

  12. Platform Settings
      - URL: `GET /api/v1/dashboard/settings/`
      - Auth: Bearer Token (Admin only)
      - Returns all key-value platform settings.
      - PATCH (Create/Update a setting):
        - URL: `PATCH /api/v1/dashboard/settings/`
        - Request Body:
          {
            "key": "max_community_members",
            "value": 500,
            "description": "Maximum members per community"
          }

20. PUBLIC APIs (PHASE 14)
--------------------------------------------------------------------------------

All endpoints under `/api/v1/public/` require NO authentication.
Responses are cached (Redis). Rate limits enforced per client IP.

Rate Limits:
  - Overview/trending/featured endpoints: 60 requests/minute
  - Per-resource endpoints: 30 requests/minute
  - Exceeded limit returns: 429 Too Many Requests

  1. Platform Statistics
     - URL: `GET /api/v1/public/stats/`
     - Auth: None
     - Cache TTL: 5 minutes
     - Success Response (200 OK):
       {
         "success": true,
         "message": "Platform statistics retrieved.",
         "data": {
           "users": 1200,
           "communities": 45,
           "channels": 210,
           "news_articles": 340,
           "events": 90
         }
       }

  2. Trending Communities
     - URL: `GET /api/v1/public/trending/communities/`
     - Auth: None
     - Cache TTL: 5 minutes
     - Returns top 10 public communities ordered by member count.
     - Response fields per community: id, name, slug, description,
       icon, banner, member_count.

  3. Featured News
     - URL: `GET /api/v1/public/featured/news/`
     - Auth: None
     - Cache TTL: 5 minutes
     - Returns latest 10 published news articles.
     - Response fields: id, title, category, image, author, community,
       published_at, likes_count.

  4. Upcoming Events
     - URL: `GET /api/v1/public/upcoming/events/`
     - Auth: None
     - Cache TTL: 5 minutes
     - Returns next 10 upcoming events ordered by start_datetime.
     - Response fields: id, title, description, start_datetime, end_datetime,
       location, is_virtual, community, organizer, banner.

  5. Community Statistics
     - URL: `GET /api/v1/public/communities/<slug>/stats/`
     - Auth: None
     - Cache TTL: 2 minutes
     - Returns stats for a single public community.
     - Response fields: id, name, slug, description, member_count,
       channel_count, news_count, event_count, upcoming_events, created_at.
     - Returns 404 for private communities.

  6. Public User Profile
     - URL: `GET /api/v1/public/profiles/<username>/`
     - Auth: None
     - Cache TTL: 2 minutes
     - Returns the public profile of a user.
     - Response fields: id, username, display_name, bio, college, branch,
       year, skills, interests, github, linkedin, portfolio, location,
       is_verified_author, profile_photo, joined.
     - Returns 404 if user not found.

  7. SEO Metadata — Community
     - URL: `GET /api/v1/public/seo/community/<slug>/`
     - Auth: None
     - Cache TTL: 10 minutes
     - Returns: title, description, canonical_url, robots, keywords.

  8. SEO Metadata — News Article
     - URL: `GET /api/v1/public/seo/news/<news_id>/`
     - Auth: None
     - Cache TTL: 10 minutes
     - Returns: title, description, canonical_url, robots, author, published_time.

  9. SEO Metadata — Event
     - URL: `GET /api/v1/public/seo/event/<id>/`
     - Auth: None
     - Cache TTL: 10 minutes
     - Returns: title, description, canonical_url, robots, start_date.

  10. Open Graph Data — Community
      - URL: `GET /api/v1/public/og/community/<slug>/`
      - Auth: None
      - Cache TTL: 10 minutes
      - Returns OG tags: og:type, og:title, og:description, og:image,
        og:url, og:site_name.

  11. Open Graph Data — News Article
      - URL: `GET /api/v1/public/og/news/<news_id>/`
      - Auth: None
      - Cache TTL: 10 minutes
      - Returns OG tags: og:type, og:title, og:description, og:image,
        og:url, og:site_name, article:author, article:published_time.

21. PRODUCTION READINESS (PHASE 15)
--------------------------------------------------------------------------------

Phase 15 does not define new REST API endpoints but adds infrastructure:

  Infrastructure:
  - Dockerfile (Python 3.12-slim, multi-stage, non-root user)
  - docker-compose.yml (services: db, redis, web, celery, celerybeat, nginx)
  - nginx/nginx.conf (HTTPS, WebSocket proxy, rate limiting, security headers)
  - entrypoint.sh (waits for DB, runs migrations, collects static files)

  Background Jobs (Celery + Celery Beat):
  - `cleanup_expired_bans` — runs daily, removes expired community bans.
  - `cleanup_expired_mutes` — runs hourly, removes expired user mutes.
  - `prune_expired_announcements` — runs hourly, deactivates expired announcements.
  - `cleanup_old_logs` — runs weekly, deletes LogEntry older than 90 days.
  - `generate_weekly_stats_snapshot` — runs weekly, saves platform stats snapshot.
  - `cleanup_orphan_search_history` — runs weekly, removes old search history.
  - `send_notification_email` — on-demand, sends transactional emails.
  - `send_bulk_announcement_email` — on-demand, sends announcement to bulk users.

  Security Headers (production.py):
  - SECURE_HSTS_SECONDS: 31536000 (1 year)
  - SECURE_HSTS_INCLUDE_SUBDOMAINS: true
  - SECURE_HSTS_PRELOAD: true
  - SECURE_SSL_REDIRECT: true
  - X_FRAME_OPTIONS: DENY
  - SECURE_BROWSER_XSS_FILTER: true
  - SECURE_REFERRER_POLICY: strict-origin-when-cross-origin
  - SESSION_COOKIE_SECURE: true
  - CSRF_COOKIE_SECURE: true

  CI/CD:
  - .github/workflows/ci.yml — runs on every PR: tests + flake8 lint
  - .github/workflows/deploy.yml — runs on main: builds Docker image,
    pushes to registry, deploys via SSH.

  Monitoring:
  - Sentry SDK (django + celery + redis integrations)
  - Rotating file logs at /app/logs/django.log (10 MB, 5 backups)
  - Health endpoint: GET /health/ and GET /api/v1/dashboard/health/

  Environment Variables (see .env.example for full list):
  - CELERY_BROKER_URL, CELERY_RESULT_BACKEND
  - EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD
  - SENTRY_DSN, SENTRY_TRACES_SAMPLE_RATE
  - DJANGO_SECURE_SSL_REDIRECT, DJANGO_SECURE_HSTS_SECONDS

  For full deployment instructions, see DEPLOYMENT.md.
